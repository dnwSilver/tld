# TLD

TLD — локальный терминальный интерфейс для учёта проектов, зависимостей, политик версий, релизов, настроек репозиториев и найденных уязвимостей.

## Запуск

Нужны Go версии из `go.mod` и терминал с поддержкой ANSI/Unicode. Часть значков требует установленного Nerd Font.

```sh
go run ./cmd/tld
```

Либо `make build` создаёт `bin/tld`, а `make install` устанавливает его в `~/.local/bin` (путь можно изменить через `INSTALL_DIR`). `make dev` открывает iTerm через AppleScript и работает только в соответствующем окружении macOS.

При запуске приложение запрашивает пароль для локальной зашифрованной SQLCipher-базы. По умолчанию путь — `os.UserConfigDir()/tld/tld.db`: на macOS обычно `~/Library/Application Support/tld/tld.db`. Точный путь зависит от ОС и окружения. Перед изменением схемы приложение создаёт рядом копию вида `tld.db.bak-v<version>-<UTC timestamp>` с правами `0600`; миграция прекращается, если копию создать не удалось. Тест восстановления проверяет, что копия старой схемы открывается и повторно мигрирует. Пароль не хранится в репозитории.

## Работа в интерфейсе

Цифры `0`–`9` переключают основные экраны, `v` открывает Vulnerabilities. `j/k` или стрелки перемещают выделение; `PageUp/PageDown` и `Home/End` перемещают его по основному списку. `/` показывает строку фильтра над таблицей: ввод сразу оставляет объекты, чьи имена содержат текст запроса (без учёта регистра). `Enter` скрывает строку ввода, сохраняя фильтр в заголовке панели: `Projects [37][search-text]`. Число видимых объектов выводится белым, текст фильтра — синим, скобки — зелёными. `j/k` или стрелки перемещают выделение по видимым строкам, `/` снова открывает ввод, `Esc` очищает фильтр и скрывает строку ввода. При переходе на другой экран фильтр сбрасывается. `Ctrl+R` повторяет загрузку текущего экрана после ошибки (на Dashboard также повторяет запрос прав); `r` обновляет текущий объект, `R` — группу объектов и может обращаться к внешним API и сканерам. Во время обновления на Projects, Dependency View, Policies, Settings, Releases и Vulnerabilities клавиша `Esc` отменяет задачу; уже сохранённые результаты остаются. Доступные действия и клавиши показаны в нижней панели текущего экрана. В остальное время `Esc` закрывает активную форму или диалог либо сообщение об ошибке.

У каждого экрана есть собственное состояние `loading / ready / stale / error`. При неудачной повторной загрузке last-good данные остаются на экране с отметкой `STALE`; `Ctrl+R` повторяет чтение. В терминале уже 72 клеток двухпанельные экраны показывают только активную панель на всю ширину, `Tab` переключает панели. Длинные navigation/operations dialogs прокручиваются вместе с выделением.

Перед применением операции, меняющей настройки удалённого проекта, интерфейс показывает источник, проект и конкретное изменение и требует повторного подтверждения. После записи приложение повторно читает целевую настройку. Если чтение не удалось или значение не подтвердилось, исход операции считается неопределённым: запись могла уже произойти, и состояние нужно проверить в удалённой системе.

## Источники и проверки

Поддерживаются источники проектов GitHub, GitLab, Gitea и Bitbucket, а также источники пакетов для npm, Go, Maven, RubyGems и CocoaPods. Указывайте URL источника целиком с `http://` или `https://`, без встроенных учётных данных. Токены хранятся в зашифрованной локальной БД и извлекаются в отдельное credential-хранилище модели для API-команды; списочная UI-модель источников токены не содержит. При редактировании токен попадает только в маскированное поле формы. Redirect и pagination на другой origin отклоняются.

| Возможность | GitLab | GitHub | Gitea | Bitbucket |
|---|---:|---:|---:|---:|
| Commit и чтение manifest | да | да | да | да |
| Branch/default branch/compare | да | да | да | да |
| Tags и release timeline | да | да | да | да |
| GitLab CI, schedules, resource groups | да | n/a | n/a | n/a |
| Protected branches/tags policy | да | n/a | n/a | n/a |
| Maintainer probe по проекту | да | n/a | n/a | n/a |
| Изменение CI/protection settings | да, с preview и readback | n/a | n/a | n/a |

`n/a` отображается как неподдерживаемая возможность, а не как провал проверки. Для GitLab итог remote mutation различает `applied`, `partial`, `uncertain` и `failed`; после `partial/uncertain` нужно проверить удалённое состояние и явно повторить операцию при необходимости.

Для поиска уязвимостей JavaScript используется `npm audit`; для мобильных стеков — OSV API/`osv-scanner` и, при подходящем lockfile, `trivy`. Наличие этих инструментов и доступность сети влияют на полноту результата. Ошибка, неподдерживаемый формат или отсутствие покрытия не трактуются как отсутствие уязвимостей. Сведения о зависимостях могут передаваться внешним npm/OSV-сервисам.

| Стек | Обязательные входы | Scanner | Отображаемое coverage |
|---|---|---|---|
| JavaScript | `package.json`; lockfile передаётся при наличии | `npm audit`, prod/dev mode | размер dependency graph из metadata, иначе `tool reported` |
| Android/Kotlin | Gradle build и версии зависимостей, которые можно точно разобрать | OSV API; `osv-scanner` как fallback | число точных OSV queries либо совпавших package/version |
| iOS/Swift | `Podfile.lock` или `Gemfile.lock` | OSV API; `osv-scanner` как fallback | число точных OSV queries либо совпавших package/version |
| Mobile lockfiles | поддерживаемый lockfile | Trivy, если установлен | число обработанных lockfile targets |

OSV-ветка требует покрытия всех разобранных зависимостей: пропущенная или неточная версия завершает попытку ошибкой, а last-good отчёт помечается `STALE`. Для каждого проекта сохраняются revision, время, scanner provenance, coverage и исход последней попытки (`complete`, `failed`, `canceled`, `unsupported`). Stdout/stderr scanner-процессов ограничен 64 MiB на поток, время процесса — пять минут, всей scan-задачи — десять минут.

У управляемой зависимости указывайте точное `registry name`, если отображаемое имя отличается от имени в manifest (`React Native` → `react-native`, `Spectrum UI Kit` → `@spectrum/ui-kit`). Сопоставление больше не удаляет дефисы, подчёркивания и другие символы: это предотвращает смешивание разных пакетов. Старые записи с именем-псевдонимом нужно уточнить после проверки копии БД.

## Проверка изменений

```sh
go test ./...
go test -race ./...
go vet ./...
go build ./cmd/tld
```

Детальный аудит, проблемы архитектуры/производительности/безопасности/юзабилити и статус их исправления находятся в [REFACTORING_AUDIT.md](REFACTORING_AUDIT.md).
